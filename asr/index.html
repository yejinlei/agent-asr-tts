🎯 ASR 是什么

自动语音识别（Automatic Speech Recognition, ASR），目标是把人类语音（声波）转换成文字。它是 Siri、小爱同学、会议转写、字幕生成、语音输入法背后的核心技术。

🗣️通俗理解：ASR = 机器的"耳朵+听写员"。你说话产生声波（空气振动），机器先把振动变成数字信号，再一层层加工，最后猜你说的是哪几个字。

ASR 的难度来自三个层面：

  • 声学层面：同一个字，不同人、不同口音、不同情绪、不同环境噪音下，波形差异巨大
  • 语言层面：同音词多（"世事/逝世/事实"），必须靠上下文语言模型消歧
  • 时序层面：语音是连续流，一个字占几帧不定，存在"对齐"问题

70 年来 ASR 经历了三次范式跃迁：模板匹配 DTW → 统计模型 GMM-HMM → 端到端神经网络 CTC/Attention/RNN-T → 大规模预训练 Whisper。下面按这个顺序展开，每个核心算法用「图示→原理→公式→手搓代码」四步法讲透。

📡 语音信号基础

声音的物理本质是空气振动。麦克风把振动转换成电压随时间变化的一维信号——这就是波形（waveform）。

📐 采样率 Sampling Rate

每秒采多少个点。电话音质 8kHz，广播 16kHz，音乐 CD 44.1kHz。ASR 常用 16kHz（奈奎斯特频率 8kHz，覆盖人声主要频段）。

🔢 量化位深 Bit Depth

每个采样点用多少 bit 表示振幅。16bit（2¹⁶=65536 级）是主流，动态范围约 96dB，足够用。

🎛️ 互动：看看不同频率是什么样

调节频率，观察单个正弦波在时域上的变化——频率越高，波形越"密"，听起来音调越高。

s(t) = 1.0 · sin(2π · 2 · t)
💡真实人声不是单一频率，而是基频（声带振动频率，男声 ≈120Hz，女声 ≈220Hz）叠加多个谐波，再经过口腔共振形成"共振峰"，构成不同元音的音色。

🔪 预处理四步曲

拿到原始波形后，不能直接喂给模型，必须先做预处理：

1

预加重 Pre-emphasis

用一阶高通滤波器 y[t] = x[t] - 0.97·x[t-1] 提升高频能量，补偿声门脉冲的高频衰减。

2

分帧 Framing

把长信号切成 25ms 一帧、帧移 10ms。16kHz 下每帧 400 点、步长 160 点。假设帧内信号"短时平稳"。

3

加窗 Windowing

每帧乘上汉明窗 w[n]=0.54-0.46cos(2πn/N)，减少帧两端的频谱泄漏（吉布斯现象）。

4

STFT 短时傅里叶

对每帧做 FFT 得到频谱，拼起来是"频谱图"Spectrogram——这是后续所有处理的基础。

🤔为什么是 25ms/10ms？ 经验值：小于 25ms 频谱不稳定，大于 25ms 帧内信号变化太大（音素已经变了）。帧移 10ms 是为了让相邻帧有 60% 重叠，避免漏掉快速变化的音素。

📊 STFT · 短时傅里叶变换

🎼 短时傅里叶变换 (STFT)

1原理图

2通俗原理

想象你在听一首很长的歌，想知道"哪一秒有鼓声"——你不能对整首歌只做一次分析，那样会丢掉时间信息。

STFT 就是"滑动小窗口听声音"：
  1. 分帧：把长信号切成 25ms 小段，相邻帧重叠 15ms（步长 10ms），保证不丢信息
  2. 加窗：每段乘汉明窗——把帧两端"压下去"，避免突然截断产生的虚假频率（频谱泄漏）
  3. 逐帧 FFT：对每个小窗口做傅里叶变换，得到这一瞬间的频率成分
  4. 拼接：把所有帧的频谱沿时间轴排开，就得到了一张"时间-频率"图：语谱图（Spectrogram）
最终产物是一个二维矩阵：横轴时间、纵轴频率、颜色深浅代表能量大小——这是 ASR 所有后续特征的起点。

3数学公式

$$X[m,k] = \sum_{n=0}^{N-1} x[n+m\cdot H] \cdot w[n] \cdot e^{-j2\pi k n / N}$$
对第 m 帧、第 k 个频率 bin 计算复频谱。先取信号从偏移 m·H 开始的 N 个点，乘窗函数，再做 N 点 DFT。
x[n]原始时域信号采样点
m帧索引，m=0,1,...,M-1
N帧长（FFT点数），通常取 512
H帧移 hop size，160点(10ms@16kHz)
w[n]窗函数，汉明窗：w[n] = 0.54 - 0.46·cos(2πn/(N-1))
k频率 bin 索引，对应频率 f_k = k·f_s/N
|X[m,k]|²功率谱（取幅度平方）

4从零手搓（纯 NumPy）

# 纯 NumPy 实现 STFT，不依赖 scipy/librosa
import numpy as np

def stft(x, n_fft=512, hop_length=160, win_length=400):
    # x: 一维原始信号，16kHz采样
    # 1. 生成汉明窗
    window = 0.54 - 0.46 * np.cos(2*np.pi*np.arange(win_length)/(win_length-1))
    # 2. 计算帧数
    n_frames = 1 + (len(x) - win_length) // hop_length
    # 3. 预分配频谱矩阵 [n_frames, n_fft//2+1]
    S = np.zeros((n_frames, n_fft//2+1), dtype=np.complex64)
    # 4. 逐帧处理
    for m in range(n_frames):
        start = m * hop_length
        frame = x[start : start+win_length]          # 取一帧
        frame = frame * window                        # 加窗
        # 补零到 n_fft 长度
        padded = np.zeros(n_fft)
        padded[:win_length] = frame
        # 做 FFT，只保留正频率部分
        spec = np.fft.fft(padded)[:n_fft//2+1]
        S[m] = spec
    # 返回幅度谱
    return np.abs(S)
💡 复制到 Python 环境直接运行，需安装 numpy。测试：x = np.random.randn(16000)（1秒随机噪声），S = stft(x)，S.shape 应为 (98, 257)。

🎵 Mel 滤波器组

🎼 Mel 滤波器组（模拟人耳感知）

1原理图

2通俗原理

人耳就像一个"粗糙的频谱分析仪"：对低频（bass鼓）分辨力强，100Hz和200Hz明显不同；对高频（金属摩擦）很迟钝，7000Hz和7500Hz听不出差别。

Mel滤波器就是在模拟人耳：造一组"三角形滤波器"，低频放很多窄的、高频放少数宽的。每个三角形响应一小段频率，把该范围内的能量累加输出一个数。80个滤波器就输出80维Mel谱，把257维线性频谱压缩成符合感知的特征。

3数学公式

$$f_{mel} = 2595 \cdot \log_{10}\left(1 + \frac{f}{700}\right)$$ $$S_{mel}[m] = \sum_{k} |X[k]|^2 \cdot H_m[k]$$
f_melMel感知频率（单位mel）
H_m[k]第m个三角滤波器在频率bin k的响应（分段线性）
S_mel[m]第m个滤波器输出的能量值
n_mels滤波器个数，ASR常用80

4从零手搓（纯NumPy）

# 纯NumPy手搓Mel滤波器组
import numpy as np

def hz2mel(f): return 2595*np.log10(1+f/700)
def mel2hz(m): return 700*(10**(m/2595)-1)

def mel_fb(n_fft=512, sr=16000, n_mels=80, fmax=8000):
    mels = np.linspace(hz2mel(0), hz2mel(fmax), n_mels+2)
    bins = np.floor((n_fft+1)*mel2hz(mels)/sr).astype(int)
    fb = np.zeros((n_mels, n_fft//2+1))
    for m in range(n_mels):
        l,c,r = bins[m], bins[m+1], bins[m+2]
        for k in range(l,c): fb[m,k]=(k-l)/(c-l)
        for k in range(c,r): fb[m,k]=(r-k)/(r-c)
    return fb
# fb = mel_fb(); S_mel = S_power @ fb.T
💡 fb.shape = (80, 257)，每行是一个三角滤波器。

📊 MFCC · 梅尔频率倒谱系数

MFCC（Mel-Frequency Cepstral Coefficients）是 ASR 历史上统治最久的特征（1980s-2010s），至今 FBank 仍是主流。它模拟了人耳对频率的非线性感知——对低频敏感、对高频粗略。

🎼 MFCC 梅尔频率倒谱系数（传统特征之王）

1原理图

2通俗原理

STFT得到的频谱有257维，相邻频率高度相关，直接给模型用冗余太多。MFCC通过七步流水线把它压缩成13维"精华"：
  1. 预加重：高通滤波，提升高频能量
  2. 分帧加窗 → FFT：得到功率谱（STFT）
  3. Mel滤波：用80个三角滤波器压缩成80维
  4. 取log：模拟人耳对响度的对数感知（分贝）
  5. DCT离散余弦变换：关键一步！把不同Mel频段的能量做去相关，类似"频谱的频谱"（倒谱cepstrum）
  6. 保留前13维：高阶系数主要是声门脉冲细节，丢弃
  7. 加Δ/ΔΔ差分：13维静态特征+13维速度+13维加速度=39维，捕捉时序变化

3数学公式

$$\text{预加重：} y[t] = x[t] - 0.97\,x[t-1]$$ $$\text{对数能量：} \hat S[m] = \log(S_{mel}[m])$$ $$c_n = \sum_{m=0}^{M-1} \hat S[m] \cdot \cos\left(\frac{\pi n(m+0.5)}{M}\right),\quad n=0,1,\dots,12$$
Ŝ[m]第m个Mel滤波器的对数能量
MMel滤波器个数（通常40或80）
c_n第n个MFCC系数，n=0是直流能量
Δ_t一阶差分：Δ_t = (c_{t+2} - c_{t-2}) / 某个加权和

4从零手搓（纯NumPy，DCT手搓）

# 完整MFCC流水线（纯NumPy，不调用scipy.fft.dct）
import numpy as np

def dct(x, n_ceps=13):
    # x: [..., M] log-Mel特征，手搓DCT-II
    M = x.shape[-1]
    n = np.arange(n_ceps)[:, None]
    m = np.arange(M)[None, :]
    # DCT-II 基矩阵
    basis = np.cos(np.pi * n * (m + 0.5) / M)  # [n_ceps, M]
    return x @ basis.T  # [..., n_ceps]

def mfcc(x, sr=16000, n_mfcc=13, n_fft=512, hop=160, n_mels=40):
    # 1. 预加重
    x = np.append(x[0], x[1:] - 0.97*x[:-1])
    # 2. STFT得功率谱（代码复用前面的stft）
    S = stft(x, n_fft, hop)
    S_pow = S**2
    # 3. Mel滤波
    fb = mel_fb(n_fft, sr, n_mels)
    S_mel = S_pow @ fb.T
    # 4. 取对数（加小常数防log(0)）
    S_log = np.log(S_mel + 1e-10)
    # 5. DCT得MFCC
    c = dct(S_log, n_mfcc)
    return c
# 注：完整版本还会加 lifter、Δ/ΔΔ，这里是核心
💡 需先定义stft()和mel_fb()（前面已实现），然后测试：mfcc(np.random.randn(16000)).shape ≈ (98, 13)。
📐Mel 刻度把 Hz 转换成感知频率。1kHz 以下近似线性，1kHz 以上近似对数——这是因为人耳基底膜上的毛细胞在低频区分布密、高频区分布稀。
⚠️深度学习时代，大家发现 DCT 这步是线性变换，神经网络自己就能学，所以现在主流用 FBank（Log-Mel 谱，省略 DCT） 作为输入特征，维数更高（80 维）但信息损失更少。

🔗 GMM-HMM · 传统 ASR 的基石

在深度学习之前，ASR 的绝对主流是 GMM-HMM。它把问题拆成两个模型：

🔊 声学模型 GMM

作用：给定一帧特征，计算它属于某个音素（状态）的概率 p(xt|st)。
做法：每个 HMM 状态对应一个高斯混合模型（通常 8-32 个高斯分量）。

🔗 时序模型 HMM

作用：建模音素/状态之间的转移概率 p(st|st-1)，处理时间对齐。
拓扑：典型三状态 left-to-right（无自回跳），对应音素的进入-稳定-离开。

HMM 的三个经典问题

问题含义算法
评估给定模型和观测序列，计算 P(O|λ)前向算法
解码给定模型和观测，找最可能的状态序列Viterbi 算法
训练给定观测序列，估计模型参数 λBaum-Welch (EM)
🧠ASR 中最常用的是Viterbi 解码——把一整段音频特征，在所有可能的音素/词序列中，找概率最大的那条路径。

🧭 Viterbi 解码 · 动态规划找最优路径

Viterbi 本质是动态规划：每个时间步每个状态，记录"到达这里的最大概率"和"从哪来的"，最后回溯得到最优路径。

🎼 Viterbi 算法（动态规划找最优路径）

1原理图

2通俗原理

想象你要从左边走到右边，每一步（每帧）你可以站在不同状态（音素）上，每个位置有"站在这里的概率"（发射概率），从i走到j有"转移概率"。

目标：找总概率最大的那条路径。

暴力枚举所有路径是指数级（3^T），不可能算完。Viterbi用动态规划——每个时间步、每个状态，只记两件事：
  1. δ：走到这里的最大概率是多少（只保留最优，其他路径丢弃）
  2. ψ：这个最大概率是从哪个状态过来的（回溯指针）
算到最后一步，找总概率最大的那个终点，然后沿着ψ指针往回走，就能还原出完整最优路径。复杂度从O(N^T)降到O(T·N²)。

3数学公式

$$\delta_t(j) = \max_i \left[\delta_{t-1}(i) \cdot a_{ij}\right] \cdot b_j(o_t),\quad \psi_t(j) = \arg\max_i \delta_{t-1}(i) \cdot a_{ij}$$ $$q_T^* = \arg\max_j \delta_T(j),\quad q_t^* = \psi_{t+1}(q_{t+1}^*)$$
δ_t(j)时刻t到达状态j的最优路径概率
a_ij从状态i转移到j的概率（转移矩阵A）
b_j(o_t)状态j发射观测o_t的概率（发射矩阵B）
ψ_t(j)回溯指针：从哪个i到j最优
q_t*最优路径在时刻t的状态

4从零手搓（纯NumPy）

# Viterbi解码：输入观测序列，输出最优状态序列
import numpy as np

def viterbi(obs, pi, A, B):
    # obs: 观测序列 [T]，每个元素是观测索引
    # pi: 初始状态概率 [N]
    # A: 转移矩阵 [N,N], A[i,j]=p(j|i)
    # B: 发射矩阵 [N,M], B[i,o]=p(o|i)
    T, N = len(obs), len(pi)
    # 用对数概率避免下溢
    log_d = np.log(pi + 1e-10) + np.log(B[:, obs[0]] + 1e-10)
    psi = np.zeros((T, N), dtype=int)
    # 递推
    for t in range(1, T):
        # [N,N] 所有i→j的概率
        scores = log_d[:, None] + np.log(A + 1e-10)
        psi[t] = np.argmax(scores, axis=0)  # 最优来源
        log_d = scores[psi[t], np.arange(N)] + np.log(B[:, obs[t]] + 1e-10)
    # 回溯
    path = np.zeros(T, dtype=int)
    path[-1] = np.argmax(log_d)
    for t in range(T-2, -1, -1):
        path[t] = psi[t+1, path[t+1]]
    return path, np.max(log_d)
💡 上面的互动Demo就是跑这段逻辑。测试：pi=[1/3,1/3,1/3]，A是left-to-right转移，B是随机发射，viterbi返回最优路径。

🤖 DNN-HMM · 深度混合时代

2012 年 Hinton 组把 GMM 换成 DNN（深度神经网络）来估计发射概率 p(s|xt)，WER 相对下降了 30%，开启了深度学习时代。

🔑 关键变化

  • GMM 建模 p(x|s)（生成式）
  • DNN 直接建模 p(s|x)（判别式）
  • 输入可以是拼接多帧（如 ±5 帧）的 FBank 特征，利用上下文

⚠️ 为什么还是 HMM？

DNN 仍然只在单帧上输出状态概率，帧间时序转移和语言模型仍靠 HMM+WFST。这是一个"神经网络替换部件"的过渡方案，不是真正的端到端。

DNN-HMM 之后还有 RNN-HMM、LSTM-HMM，但真正的革命是 CTC / Attention 让模型直接输出字符序列——跳过了音素、HMM、解码图等手工设计。

⚡ CTC · 连接时序分类

CTC（Connectionist Temporal Classification，Graves 2006/2014）是端到端 ASR 的开山之作，解决了一个核心难题：输入输出长度不等、无法帧级对齐时如何训练。

🎼 CTC（连接时序分类，端到端对齐核心）

1原理图

2通俗原理

语音输入可能有100帧，但标签只有"hi"两个字符——帧数≠字数，而且不知道哪个帧对应"h"哪个对应"i"，这就是对齐问题。

CTC的天才想法：引入一个特殊符号ε（blank空白），允许模型输出：
  • ε："我现在什么都没说，还在停顿"
  • 重复字符："我还在说这个字"
解码时用B-归约：先把连续重复的字符合并，再删掉所有ε。这样一来，"hhεii"、"εhεiε"、"hhhii"、"hiεεε"都归约成"hi"。

训练时，所有能归约成"hi"的路径都是对的——我们要把所有合法路径的概率加起来，这就是"连接时序分类"名字的由来。用前向-后向动态规划高效计算，不用枚举指数级路径。

3数学公式

$$P(Y|X) = \sum_{\pi \in B^{-1}(Y)} \prod_{t=1}^{T} y_t(\pi_t)$$ $$\alpha(t,u) = \big(\alpha(t-1,u) + \alpha(t-1,u-1) + \alpha_{\text{skip}}(t-1,u-2)\big) \cdot y_t(l_u)$$
α(t,u)表示前t帧、走到扩展标签序列第u个位置的总概率。扩展标签序列l是在真实标签每个字符前后都插入ε，如"hi"→[ε,h,ε,i,ε]。转移规则：可以停在原地、走到下一个；当l_u是真实字符且≠l_{u-2}时，可以跳过一个ε。
B(π)归约函数：合并重复→删ε，得到真实标签
B⁻¹(Y)所有能归约成Y的CTC路径集合
y_t(c)第t帧输出字符c的概率（模型softmax输出）
l扩展标签序列（插入ε后，长度2U+1）
α(t,u)前向变量：前t帧走到l_u的总概率

4从零手搓（纯NumPy实现CTC前向）

# CTC前向算法：计算 P(Y|X)，不用torch.nn.CTCLoss
import numpy as np

def ctc_loss(log_probs, targets, blank=0):
    # log_probs: [T, C] 每帧各字符的对数概率
    # targets: 目标标签序列（不含blank），list[int]
    T, C = log_probs.shape
    U = len(targets)
    # 1. 构建扩展序列：ε t0 ε t1 ε ... ε tU ε，长度=2U+1
    l = []
    for t in targets:
        l.extend([blank, t])
    l.append(blank)
    L = len(l)  # 2U+1
    # 2. 初始化α：t=0时，只能从第0个ε或第1个真实字符开始
    alpha = np.full((T, L), -np.inf)
    alpha[0, 0] = log_probs[0, l[0]]
    alpha[0, 1] = log_probs[0, l[1]]
    # 3. 前向递推（对数空间加法用logsumexp）
    for t in range(1, T):
        for u in range(L):
            # 三个来源：(t-1,u)停留、(t-1,u-1)前进一步
            acc = alpha[t-1, u]
            if u - 1 >= 0:
                acc = np.logaddexp(acc, alpha[t-1, u-1])
            # skip：l_u是真实字符且不等于l_{u-2}，可跳过ε
            if u - 2 >= 0 and l[u] != blank and l[u] != l[u-2]:
                acc = np.logaddexp(acc, alpha[t-1, u-2])
            alpha[t, u] = acc + log_probs[t, l[u]]
    # 4. 终点两个ε（最后和倒数第二个位置）
    log_p = np.logaddexp(alpha[T-1, L-1], alpha[T-1, L-2])
    return -log_p  # 返回负对数似然（loss）
💡 全程在对数空间计算避免数值下溢，用np.logaddexp做log-sum-exp。6帧预测"hi"的演示就是这套α递推。
🧮为什么要求和而不是取 argmax？因为同一句话可以对应很多条合法路径（blank 插在哪、重复几次都可以），训练时必须把所有合法路径的概率加起来作为该标签序列的似然。

🎯 Attention · 缩放点积注意力

CTC 的条件独立假设太强。Attention 机制让模型在每一步预测时，都能"回头看"输入序列的所有位置，按需聚焦最相关的信息——这是 Transformer 和 LAS 模型的核心。

🎼 缩放点积注意力（QKV图书馆检索）

1原理图

2通俗原理

就像你去图书馆查资料：
  1. Q（Query）：你脑子里的问题——"我想知道ASR里的CTC是什么"
  2. K（Key）：每本书的索引标签——《语音识别》《深度学习》《图像处理》……
  3. Q·K^T 相似度：你把问题和每本书标签做比对，《语音识别》匹配度0.9、《深度学习》0.3、《图像处理》0.01
  4. Softmax归一化：把匹配度变成概率权重，加起来=1，比如[0.7, 0.25, 0.05]
  5. V（Value）：每本书的实际内容
  6. 加权求和：70%的内容来自《语音识别》、25%来自《深度学习》、5%来自其他——这就是你"注意"到的上下文
注意这是"软"注意力：你不只是挑一本书，而是所有书都看一点，相关的多看、不相关的少看。除以√d_k是为了防止点积值过大导致softmax饱和（梯度消失）。

3数学公式

$$\text{Attention}(Q,K,V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V$$
Q查询矩阵 [T_q, d_k]，解码器每步一个向量
K键矩阵 [T_k, d_k]，编码器每个位置一个向量
V值矩阵 [T_k, d_v]，编码器内容表示
d_kQ/K的维度，缩放因子，防止点积方差过大
QK^T相似度矩阵 [T_q, T_k]，每对(query,key)的匹配度
softmax归一化成注意力权重α，每行加起来=1
输出[T_q, d_v]，每个query对应的上下文向量

4从零手搓（纯NumPy，含手搓softmax）

# 缩放点积注意力：纯NumPy实现，不调用torch高层API
import numpy as np

def softmax(x, axis=-1):
    # 减max防溢出
    e = np.exp(x - np.max(x, axis=axis, keepdims=True))
    return e / e.sum(axis=axis, keepdims=True)

def scaled_dot_product_attention(Q, K, V, mask=None):
    # Q: [T_q, d_k], K: [T_k, d_k], V: [T_k, d_v]
    d_k = Q.shape[-1]
    # 1. 计算相似度 [T_q, T_k]
    scores = Q @ K.T / np.sqrt(d_k)
    # 2. 可选mask：屏蔽未来位置（解码时用）
    if mask is not None:
        scores = np.where(mask, scores, -np.inf)
    # 3. softmax得权重
    attn = softmax(scores, axis=-1)
    # 4. 加权求和V → [T_q, d_v]
    out = attn @ V
    return out, attn

# 测试：T_q=1(当前步), T_k=5(5个输入帧), d=64

LAS（Listen, Attend, Spell）

👂 Listen（编码器）

金字塔 BLSTM 把语音帧下采样 8 倍，得到高层声学表征 h。

🎯 Attend（注意力）

每步预测一个对编码器输出的加权分布 αt，得到上下文向量 ct=Σαtihi。

✍️ Spell（解码器）

LSTM 以 (yt-1, ct, st-1) 为输入，自回归输出下一个字符。

🆚CTC vs Attention：CTC 快（可流式）但弱建模，Attention 强但慢（自回归）且对齐不稳定。工业系统常用 CTC+Attention 联合训练（如 ESPnet、Conformer 模型），推理时 CTC 做前缀剪枝 + Attention 打分。

🔄 RNN-T · Transducer

RNN-T（Recurrent Neural Network Transducer，Graves 2012）被认为是 CTC 和 Attention 之间的"完美平衡"：既不需要外部对齐，又能流式输出，还能建模输出间依赖。

三部分组成

  • Encoder（转录网络）：处理声学特征
  • Prediction Network：类似 RNN-LM，处理已输出标签
  • Joint Network：融合两者输出，在每步决定"输出新标签"还是"继续听（blank）"

为什么工业界偏爱 RNN-T？

① 天然流式（无需看全句）；② 自带标签依赖建模（比 CTC 准）；③ 不需要像 Attention 那样对齐稳定。Google、Meta 的主流流式 ASR 都是 RNN-T。

🧱 Conformer · CNN+Transformer 的融合

2020 年 Google 提出 Conformer，把 Transformer（长程建模）和 CNN（局部特征）结合起来，至今仍是非大模型时代最强 ASR 编码器。

Conformer Block 结构（Macaron 结构）

ConformerBlock(x):
  x = x + ½·FFN(x)               # 前 FFN（Macaron）
  x = x + MHSA(x)                 # 多头自注意力（长程）
  x = x + ConvModule(x)           # 深度可分离卷积 + 门控 + Swish（局部）
  x = x + ½·FFN(x)                # 后 FFN
  x = LayerNorm(x)
  return x
💡为什么要双 FFN（Macaron）？论文发现把 FFN 拆成两半放在注意力+卷积两侧，每层总参数量减半但效果更好。这是一个实验结论，没有深刻理论，但非常好用。

🌐 Whisper · 大规模多语言预训练

2022 年 OpenAI 发布 Whisper，用 68 万小时（438 万小时有标签）多语言语音-文本对训练了一个简单的 Encoder-Decoder Transformer，效果惊人地好——鲁棒、零样本迁移到口音/噪音、99 种语言。

模型设计（故意很朴素）

  • 输入：80 维 Log-Mel，25ms 窗、10ms 步长
  • Encoder：2 层 CNN 下采样 2×，接 N 层 Transformer Encoder
  • Decoder：Transformer Decoder，特殊 token 控制任务（<|transcribe|>/<|translate|>/<|zh|>）
  • 没有 CTC、没有 Conformer、没有流式优化

为什么这么强？

  • 数据规模碾压：68 万小时是前人的 10-100 倍
  • 多任务：同时做转写、翻译、语音活动检测、语种识别
  • 弱标注过滤：用 Kaldi 大模型筛掉错配的字幕对
  • 简单就是好：抛弃了所有复杂技巧，纯 Transformer + 大数据

💻 源码走读 · Kaldi HMM 拓扑

Kaldi 是传统 ASR 的经典框架，理解它的 TransitionModel 是理解 HMM-ASR 的钥匙。下面是核心概念的伪代码：

// Kaldi 中三状态 HMM 拓扑（每个音素 = 3 个状态）
class HmmTopology {
  // 每个音素 3 状态，状态 0/1/2，0 不能到 2（left-to-right）
  TopologyEntry states[] = {
    {0, { {0, 0.5}, {1, 0.5} }},  // 状态0：自环 0.5、到1 0.5
    {1, { {1, 0.5}, {2, 0.5} }},  // 状态1：自环 0.5、到2 0.5
    {2, { {2, 0.5}, {-1, 0.5} }}  // 状态2：自环 0.5、结束 -1 0.5
  };
};

// Viterbi 核心：动态规划
for t = 1; t < T; t++ {
  for each state j {
    // 找从哪个状态 i 过来概率最大
    best_i = argmax_i ( viterbi[t-1][i] * log_a[i][j] )
    viterbi[t][j] = viterbi[t-1][best_i] + log_a[best_i][j] + log_b[j][o[t]]
    backptr[t][j] = best_i
  }
}
// 回溯得到最优路径
path[T] = argmax_j viterbi[T][j]
for t = T-1; t >= 0; t--
  path[t] = backptr[t+1][path[t+1]]
